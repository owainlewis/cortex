# Issues 132 and 134 plan

## Task

Keep atomic-save temporary inodes private while file contents are written and synced, then apply preserved metadata only immediately before commit.
Use a fixed-size sibling temporary name that stays within macOS `NAME_MAX` for every valid target basename.

## Acceptance criteria

- The content-bearing temporary save inode is owner-only and has no inherited ACL.
- A world-writable source mode or write-granting ACL is not copied before buffer contents are written and synced.
- Existing mode, ownership, ACLs, flags, and extended attributes are applied immediately before the atomic rename.
- New files retain the existing umask-derived final mode and inherited ACL.
- Metadata failures leave the original target untouched and remove only the temporary inode Cortex created.
- The temporary basename has an explicit byte bound independent of the target basename.
- Valid target basenames near `NAME_MAX`, including multibyte names, save successfully.
- Temporary-name collisions are retried with collision-resistant randomness.
- Hostile temporary symlinks, target races, symlink saves, and metadata preservation retain their existing behavior.

## Implementation

1. Atomically create the content-bearing sibling temporary file with an explicit owner-only mode and no inherited ACL.
2. Write and sync the new contents before copying any source metadata.
3. Use an empty randomized sibling probe to derive a new file's final mode and inherited ACL without changing the process umask.
4. Remove the probe name before creating the private save inode, then apply and sync the captured metadata only in the final metadata phase.
5. Revalidate the target, copy and sync metadata, and commit without moving metadata work earlier in the transaction.
6. Stop copying the target basename into the temporary component.
7. Keep the random suffix and fixed Cortex prefix and extension within a documented byte bound.
8. Add focused hook tests for private mode and ACL state during write and sync, plus final metadata immediately before commit.
9. Add near-`NAME_MAX`, multibyte, byte-safety, collision, and hostile-symlink regression coverage.

## Checks

- Reproduce the permissive temporary inode and overlong temporary-name failures before the fix.
- Run focused buffer tests.
- Run `cargo fmt -- --check`.
- Run `git diff --check`.
- Run `cargo test --all-targets`.
- Run `cargo clippy --all-targets --all-features -- -D warnings`.
- Run `cargo build --all-targets`.
- Manually save and exit in a PTY, confirm the saved bytes, and confirm exact terminal restoration and a usable shell.
- Apply the `improve` workflow to the final diff without changing behavior.
- Obtain a fresh independent review and address every important finding.
